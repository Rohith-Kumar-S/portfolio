The Problem: Autonomous vehicles must predict the mutually influential behavior of other agents at complex intersections. While models like GameFormer excel at this using vectorized data and game theory, they lack visual context—they know what happened, but not why (e.g., a pedestrian vs. a road hazard).

In this work, we investigate whether adding camera to- kens as a complementary modality can enrich the model’s understanding of the scene. Camera tokens are pre-computed visual embeddings provided by the Waymo Open Dataset, representing compressed features from 8 surrounding cameras across 11 timesteps. We integrate these tokens along with LiDAR data from 5 sensors into the GameFormer pipeline and evaluate their effect on interaction prediction performance

GameFormer Architecture

GameFormer models joint trajectory prediction as a game-theoretic problem. The model consists of a Transformer-based encoder and an iterative level-k decoder. The encoder processes agent states and map features into a shared latent representation. The decoder then performs iterative reasoning, where each agent's predicted trajectory at level $k$ is conditioned on the predicted trajectories of other agents at level $k-1$. This process produces jointly consistent multi-modal trajectory predictions for all interacting agents.

Dataset

We use the Waymo Open Dataset Motion v1.3, which provides richly annotated real-world driving scenarios. Each scenario contains 11 timesteps of historical agent states including position, velocity, heading, and object type, along with vectorized map features such as lane boundaries, crosswalks, and traffic signals. We train and evaluate on 3 shards of the training split and one shard of the validation split, containing approximately 13,000 and 3,000 scenarios respectively.

Camera Tokens

The Waymo Open Dataset provides pre-computed visual features as 256-dimensional embeddings from 8 cameras across 11 timesteps, yielding an $(11, 8, 256)$ tensor per scenario. These map to distinct integers in Waymo's codebook to form 32-dimensional embeddings, enabling direct use as compact model inputs without further encoding overhead.

LiDAR Data

We utilize 3D point cloud spatial data extracted across 11 timesteps (1.0s history) from five sensors: one mid-range (75m limit) and four short-range (20m limit). Using the provided extrinsic calibration matrices, the point clouds—which are restricted to the top two intensity returns—are transformed from the global frame into the vehicle frame.

Data Pipeline

The scenario data and sensor data are stored separately in the Waymo Google Cloud Storage bucket. We merge them by matching on scenario ID using \texttt{gsutil}, downloading the corresponding lidar and camera tfrecord for each scenario and merging the sensor data into the scenario tfrecord. The merged tfrecord is then processed by our data pipeline, which extracts vectorized agent and map features alongside LiDAR data and camera tokens, and saves them as compressed \texttt{.npz} files for training. Each scenario contains 11 frames of corresponding camera tokens and LiDAR data. The data pipeline processes these scenarios by individual interaction pairs. For each pair, the global LiDAR point cloud is transformed into an agent-centric coordinate system by shifting the origin to the center of the interacting agent. Discussion and Summary

  • Performance Gains: Integrating camera tokens into GameFormer consistently improves prediction accuracy across all horizons, reducing minADE by 12% (at 5s) to 7.5% (at 15s), with similar gains in minFDE.
  • Training Convergence: Due to limited training data (~13,000 scenarios), both the baseline and camera models overfit by epoch 15–17.
  • LiDAR Stability: In contrast, the LiDAR-fused model exhibits highly stable convergence, acting as a strong regularizer. We hypothesize that fixing the current spatial downsampling bottleneck and scaling the dataset will allow the LiDAR model to achieve the best overall generalization.

Limitations

  • Dataset Size: Training on a limited subset restricts full generalization.
  • Feature Extraction: Using pre-computed camera embeddings prevents the model from learning low-level visual features directly.
  • Spatial Granularity: Aggressive LiDAR downsampling and a coarse 0.5m Bird’s-Eye View (BEV) resolution discard critical fine-grained details, particularly for smaller agents like pedestrians.
  • Boundary Artifacts: Padding missing timesteps with origin coordinates for agents that exit the sensor range creates artificial U-turn trajectories.
